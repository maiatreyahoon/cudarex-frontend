# Demo video script

Target length: 2 minutes 50 seconds. Record the application actually working. The narration below is approximately 320 words, leaving time for clicks. No third-party music is needed.

## Recording prerequisites

Use a clean demo profile with sample data. Start both services and finish one successful runtime call to an available NVIDIA open-source model through Nebius. Confirm the model status shows real success metadata. Never show a key, terminal environment, private memories or account credentials.

If live verification is not complete, use this as a rehearsal only. A deterministic fallback recording does not demonstrate the required provider/model runtime.

## 0:00–0:18 — The user and problem

Screen: dashboard, then Memory Centre.

“CUDAREX is a personal AI workspace. AURA is the assistant. We built it for a student who wants help learning and planning while keeping control of personal context. Here I save a preference for short explanations with examples. I can inspect, correct or delete it.”

Action: save one preference, show its record.

## 0:18–0:48 — Practice and evidence

Screen: Learning Studio.

“I choose a practice problem and try an answer. AURA checks it and explains this mistake. A hint gives me the next step. I try again, then see the result in my learning profile. The numerical grading covers this curated problem bank. If I reveal a solution first, the app records my answer as assisted practice.”

Action: start Newton’s second law problem, submit 20, request a hint, submit 5, show counters. Do not claim general homework grading.

## 0:48–1:20 — Actual NVIDIA model use

Screen: Chat with AURA and model status.

“Here is AURA’s generated response through Nebius Token Factory, using [say the exact verified NVIDIA model]. The key stays on the server. I can choose whether the request includes relevant saved memories. The status records this successful runtime call. Model output supplies advice, while server code retains action authority.”

Action: make a genuine request, wait for the result, show the requested/returned model evidence. Replace the bracketed instruction before recording. Never narrate an API stub as a live call.

## 1:20–1:47 — Reusable skill and approval

Screen: Skills Centre.

“I create a reusable skill with instructions and a workflow. Feedback produces an improvement proposal. The current instructions stay unchanged until I approve. Approval creates a new version, and I can inspect the previous version. A skill’s tool list does not grant permissions.”

Action: show a prepared Project Planner skill, feedback proposal, approve, expand history.

## 1:47–2:23 — Exact calendar proposal

Screen: Integrations briefly, then Security Centre.

“Calendar is explicitly a local mock in this release. I choose the event title and time, inspect the proposal, and approve it. The server checks permission and conflicts again before storing the event. I can download a calendar file and choose whether to import it myself. No external account action happens behind the scenes.”

Action: enable mock calendar, propose a nonconflicting event, approve, show event and download link.

## 2:23–2:50 — Audit and close

Screen: Activity Centre, then dashboard.

“The activity timeline shows the route and decisions. My memory, practice and approved skill changes survive a restart. CUDAREX brings personal context and useful workflows into one inspectable product. We are now validating the student experience. Live account integrations and a hosted always-on service are future work.”

Action: filter activity. End on dashboard. Keep the final video below three minutes.

## Final recording review

Watch the entire exported recording. Check that the model call is real, the exact model name is readable, mock labels remain visible, no secrets appear, audio matches the screen, and the video ends before three minutes. Upload publicly to YouTube only after review. Paste that URL into Devpost yourself or authorize a separate publication action.
